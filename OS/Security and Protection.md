##  Security and Protection
**Security**는 컴퓨터 시스템에서 사용자 인증(authentication)을 수행하여 **데이터와 코드의 무결성(integrity)** 을 보호하고, 컴퓨터 시스템의 **물리적 자원(physical resources)** 이 무단으로 사용되거나 손상되지 않도록 보장하는 기능이다. 즉, 시스템에 접근하는 사용자가 실제로 허가된 사용자임을 확인하고, 중요한 정보와 시스템 자원을 안전하게 유지하는 역할을 한다.

**Protection**은 운영체제가 시스템 자원에 대한 접근을 제어하는 메커니즘으로, 운영체제로부터 적절한 권한을 부여받은 프로세스만이 메모리 영역, CPU, 그리고 기타 시스템 자원에 접근하거나 사용할 수 있도록 보장한다. 이를 통해 하나의 프로그램이나 사용자가 다른 프로그램이나 시스템 전체에 피해를 주는 것을 방지한다. 사용자가 시스템에 접근할 수 있는 범위와 방식(access type)을 제한함으로써 시스템 접근을 통제한다.

**Computer resources**는 사용자나 프로그램에 의해 의도적으로 또는 실수로 잘못 사용될 가능성이 있다. 예를 들어 사용자가 실수로 중요한 데이터를 삭제할 수도 있고, 악의적인 공격자가 시스템을 파괴하거나 정보를 훔치려고 할 수도 있다.

따라서 이러한 문제를 방지하기 위해 공격을 예방하거나 탐지할 수 있는 보안 메커니즘이 필요하다. 이러한 보안 기술 중에서 암호학은 중요한 보안 수단으로 사용되며, 데이터를 암호화하여 권한이 없는 사용자가 내용을 읽거나 변경하지 못하도록 보호하는 역할을 한다.

일반적으로 Security(보안)는 컴퓨터 자원을 다양한 위협으로부터 보호하는 것을 의미하며, 특히 다음과 같은 상황을 방지하는 것을 포함한다.

- 허가되지 않은 접근(unauthorized access)으로부터 시스템과 데이터를 보호하는 것
- 악의적인 파괴나 변경(malicious destruction or alteration)으로부터 시스템 자원을 보호하는 것
- 사용자의 실수나 시스템 오류로 인해 데이터의 불일치(inconsistency)가 발생하는 것을 방지하는 것

### Security Violations
컴퓨터 시스템의 보안 정책이 위반되는 상황을 의미한다. 이러한 보안 위반은 시스템의 데이터, 자원, 서비스 등에 피해를 줄 수 있으며 다양한 형태로 발생할 수 있다.

Threat(위협)은 보안 위반이 발생할 가능성(potential)을 의미하며, 대부분 우연하거나 의도되지 않은 상황에서 발생할 수 있다. 즉, 실제 공격이 일어나지 않았더라도 시스템에 위험이 존재하는 상태를 말한다.

Attack(공격)은 보안을 깨뜨리기 위해 의도적으로 이루어지는 시도를 의미하며, 일반적으로 <span style="color:orange">악의적인 목적(malicious)</span>을 가지고 수행된다. 공격자는 시스템에 침입하거나 데이터를 훔치거나 서비스를 방해하려는 목적을 가진다.

보안 위반의 주요 유형은 다음과 같다.
```
- Breach of confidentiality (기밀성 침해)
허가되지 않은 사용자가 시스템의 데이터를 읽거나 접근하여 비밀 정보가 외부로 유출되는 경우를 의미한다. 예를 들어 개인정보나 기업의 기밀 문서가 외부로 노출되는 상황이 이에 해당한다.

- Breach of integrity (무결성 침해)    
데이터가 허가 없이 수정, 변조, 또는 삭제되는 경우를 의미한다. 이 경우 데이터의 정확성과 신뢰성이 손상된다.

- Breach of availability (가용성 침해)
정당한 사용자가 필요할 때 시스템이나 서비스에 접근하지 못하는 상황을 의미한다. 시스템 장애나 공격으로 인해 서비스가 중단될 때 발생한다.

- Theft of service (서비스 도용)
권한이 없는 사용자가 시스템 자원이나 서비스를 무단으로 사용하는 경우를 의미한다. 예를 들어 다른 사용자의 계정을 이용해 서버 자원을 사용하는 경우가 이에 해당한다.

- Denial of Service (DoS)
시스템이나 네트워크에 과도한 요청을 보내 정상적인 서비스 제공을 방해하는 공격을 의미한다.

- Distributed Denial of Service (DDoS)
여러 대의 컴퓨터가 동시에 공격을 수행하여 대량의 트래픽을 발생시켜 시스템을 마비시키는 DoS 공격의 확장 형태이다.
```
> Security Violations는 시스템의 **기밀성(confidentiality), 무결성(integrity), 가용성(availability)** 을 위협하는 다양한 형태의 보안 침해를 포함한다.

### Four Levels of Security
퓨터 시스템을 안전하게 보호하기 위해 고려해야 하는 네 가지 보안 계층(level)을 의미한다. 각 계층은 서로 다른 방식으로 시스템을 보호하며, 모든 계층이 함께 작동해야 전체 시스템의 보안이 유지된다.

- Physical Security(물리적 보안): 컴퓨터 시스템이 침입자(intruder)에 의해 물리적으로 접근되지 않도록 보호하는 것을 의미한다. 예를 들어 서버실 출입 통제, 잠금 장치, 감시 카메라, 생체 인증 등을 사용하여 허가되지 않은 사람이 컴퓨터 장비에 직접 접근하지 못하도록 한다.

- Network Security(네트워크 보안): 트워크를 통해 이루어지는 공격으로부터 시스템을 보호하는 것을 의미한다. 네트워크는 외부와 연결되어 있기 때문에 보안 측면에서 위험 요소가 될 수 있다. 따라서 방화벽, 암호화, 침입 탐지 시스템 등을 사용하여 네트워크를 통한 불법 접근이나 공격을 방지해야 한다.

- Operating System Security(운영체제 보안): 운영체제는 시스템 자원을 관리하는 핵심 소프트웨어이기 때문에 보안이 매우 중요하다. 운영체제는 공격 가능 영역(attack surface)을 최소화하고, 시스템 침투(penetration)를 방지하도록 설계되어야 한다. 이를 위해 접근 권한 관리, 사용자 인증, 프로세스 보호 등의 기능이 필요하다.

- Application Security(응용 프로그램 보안): 응용 프로그램 자체에 존재할 수 있는 **보안 취약점이나 버그(security bugs)**로부터 시스템을 보호하는 것을 의미한다. 프로그램 코드의 오류나 취약점은 공격자가 시스템에 침입하는 통로가 될 수 있기 때문에, 안전한 프로그래밍과 지속적인 보안 점검이 필요하다.

> 컴퓨터 보안은 물리적 보안 → 네트워크 보안 → 운영체제 보안 → 응용 프로그램 보안과 같은 여러 계층에서 동시에 이루어져야 시스템 전체를 효과적으로 보호할 수 있다.

---

### Security Holes in Programs (or Processes)
프로그램이나 프로세스 내부에 존재하는 보안 취약점(security vulnerability)을 의미하며, 이러한 취약점은 공격자가 시스템을 침해하거나 손상시키는 데 이용될 수 있다.

- Malware(악성 소프트웨어): 컴퓨터 시스템을 악용하거나(exploit), 기능을 방해하거나(disable), 손상시키기 위해 의도적으로 만들어진 소프트웨어를 의미한다.
  - Trojan horse는 정상적인 프로그램처럼 보이지만 내부에 악성 기능을 숨겨 놓은 프로그램
  - spyware는 사용자의 정보를 몰래 수집
  - ransomware는 데이터를 암호화한 뒤 금전을 요구하고
  - backdoor는 인증 절차를 우회하여 시스템에 접근할 수 있는 통로를 제공
  - logic bomb은 특정 조건이 충족될 때 악성 동작을 수행하도록 설계된 코드

- Code Injection(코드 삽입 공격): 대부분의 소프트웨어가 악성 프로그램이 아님에도 불구하고 발생할 수 있는 심각한 보안 위협이다. 공격자가 프로그램의 취약점을 이용하여 외부에서 악성 코드를 프로그램 내부에 삽입하고 실행시키는 공격 방식을 말한다. 이러한 공격은 입력 검증이 제대로 이루어지지 않을 때 자주 발생하며, 시스템의 권한을 탈취하거나 데이터를 변조하는 데 사용될 수 있다.

- Viruses와 Worms는 스스로 복제하여 확산되는 악성 코드의 대표적인 형태이다.
  - Virus(바이러스)는 정상적인 프로그램 내부에 코드 조각(fragment) 형태로 삽입되어 있으며, 실행되면 스스로 복제하여 다른 프로그램을 감염(infect)시키도록 설계되어 있다.
  - Worm(웜)은 네트워크를 이용하여 사람의 개입 없이 스스로 복제하고 다른 시스템으로 확산되는 특징을 가진다.

### Threats in the System and the Network
시스템 내부나 네트워크를 통해 발생할 수 있는 다양한 보안 위협을 의미한다. 이러한 위협은 시스템의 정보 유출, 서비스 중단, 또는 취약점 탐지와 같은 문제를 일으킬 수 있다.

- Attacks via Network Traffic(네트워크 트래픽을 통한 공격): 네트워크로 전달되는 데이터 흐름을 이용하여 이루어지는 공격이다. 그 대표적인 예로 sniffing과 spoofing이 있다.
  - Sniffing은 공격자가 네트워크에 수동적으로(passive) 존재하면서 전송되는 네트워크 트래픽을 몰래 가로채어(intercept) 데이터를 수집하는 방식이다. 이 방법을 통해 로그인 정보나 중요한 데이터를 탈취할 수 있다.

  - Spoofing은 공격자가 **정상적인 사용자나 시스템인 것처럼 가장(masquerading)**하여 통신에 참여하는 공격 방식이다. 또한 공격자가 중간자(man-in-the-middle) 역할을 하여 두 사용자 사이의 통신을 가로채고, 데이터를 읽거나 수정할 수도 있다.

- Denial of Service(DoS): 시스템을 공격하여 정상적인 사용자가 서비스를 이용하지 못하도록 만드는 공격이다. 이 공격은 정보를 훔치거나 자원을 직접적으로 탈취하는 것이 목적이 아니라, 시스템이나 네트워크를 마비시켜 정상적인 서비스 제공을 방해하는 것을 목표로 한다.

- Port Scanning: 특정 시스템의 열려 있는 포트(open ports)를 조사하여 취약점을 찾는 방법이다. 이는 그 자체로 직접적인 공격은 아니지만, 시스템의 취약점을 발견하기 위한 사전 단계로 사용되는 경우가 많다. 또한 이러한 과정은 시스템의 특징을 분석하여 사용 중인 운영체제(OS)의 종류를 추론하는 fingerprinting 과정의 일부로 활용되기도 한다.


## Cryptography as a Security Tool
네트워크 환경에서 데이터를 안전하게 전달하기 위해 사용하는 보안 기술이다.

네트워크로 연결된 컴퓨터 시스템에서는 메시지를 보내는 송신자(sender)와 메시지를 받는 수신자(receiver)가 존재하며, 메시지는 네트워크를 통해 전달된다. 그러나 네트워크는 외부 공격자가 접근할 수 있는 환경이기 때문에 메시지가 가로채지거나 변조될 위험이 있다.


운영체제나 시스템은 단순히 네트워크 자체를 신뢰할 수 없기 때문에, 메시지가 안전하게 전달되도록 보장하는 방법이 필요하다. 바로 이러한 역할을 하는 것이 **Cryptography**(암호학)이다.

암호학의 목적은 네트워크를 신뢰하지 않아도 메시지의 안전성을 보장할 수 있도록 하는 것이다. 즉, 네트워크가 공격자에게 노출되어 있더라도 데이터가 보호되도록 한다.

암호학은 Key(키)라고 불리는 비밀 정보를 기반으로 동작한다. 이 키는 네트워크에 있는 특정 컴퓨터들 사이에서 선택적으로 배포(selectively distributed)되며, 메시지를 처리하는 데 사용된다. 키를 이용하여 메시지를 암호화(encrypt)하면 원래의 내용을 알아볼 수 없는 형태로 변환되고, 올바른 키를 가진 수신자만이 메시지를 복호화(decrypt)하여 원래의 내용을 확인할 수 있다.

---

### Encryption
메시지를 안전하게 전달하기 위해 원래의 메시지를 읽을 수 없는 형태로 변환하는 과정이다. 이를 통해 송신자는 특정 key를 가진 수신자만이 메시지를 읽을 수 있도록 보장할 수 있다. 즉, 메시지가 네트워크를 통해 전달되는 동안 공격자가 내용을 가로채더라도 key가 없으면 메시지를 이해할 수 없도록 만든다.

Encryption 알고리즘은 여러 가지 구성 요소로 이루어져 있다. 먼저 key의 집합인 K가 있으며, 이는 메시지를 암호화하거나 복호화하는 데 사용되는 비밀 정보의 집합이다. 다음으로 message의 집합인 M이 있는데, 이는 암호화되기 전의 원래 메시지들을 의미한다. 또한 ciphertext의 집합인 C가 있으며, 이는 메시지가 암호화되어 생성된 읽을 수 없는 형태의 데이터이다.

암호화 과정은 encryption function E를 통해 이루어진다. 이 함수는 key와 message를 입력으로 받아 message를 ciphertext로 변환한다. 즉, E : K → (M → C)의 형태로 표현되며, 특정 key를 사용하여 message를 ciphertext로 바꾸는 역할을 한다.

반대로 복호화 과정은 decryption function D를 통해 이루어진다. 이 함수는 ciphertext를 다시 원래의 message로 되돌리는 역할을 한다. 즉, D : K → (C → M)의 형태로 표현되며, 올바른 key를 사용해야만 ciphertext를 원래의 message로 복원할 수 있다.

---

### The essential property of encryption algorithm
Encryption 알고리즘의 가장 중요한 성질은 올바른 key를 가진 경우에만 암호문을 복호화할 수 있다는 점이다. 암호화 과정에서 사용된 key를 알고 있어야만 해당 암호문이 어떤 메시지에서 생성되었는지를 알아낼 수 있다.

key를 보유한 컴퓨터는 암호문(ciphertext)을 복호화하여 원래의 평문(plaintext)을 얻을 수 있다. 반면에 key를 가지고 있지 않은 컴퓨터는 암호문을 복호화할 수 없다. 이로 인해 허가되지 않은 사용자가 메시지의 내용을 알아내는 것이 어렵게 된다.

또한 일반적으로 암호문(ciphertext)은 네트워크를 통해 공개된 상태로 전달되기 때문에 공격자가 쉽게 볼 수 있다. 그렇기 때문에 암호문을 분석하더라도 그로부터 key를 계산하거나 유추하는 것이 현실적으로 불가능(infeasible)하도록 설계되는 것이 매우 중요하다.

Encryption 알고리즘은 크게 두 가지 유형으로 나눌 수 있다.
- symmetric encryption(대칭 키 암호화): <span style="color:orange">이 방식에서는 메시지를 암호화할 때와 복호화할 때 동일한 key가 사용된다.</span>

    송신자와 수신자가 같은 key를 공유해야 하며, 이 key를 이용하여 메시지를 암호화하고 다시 원래의 메시지로 복호화할 수 있다. 따라서 이  방식에서는 key의 비밀성이 매우 중요하며, 만약 공격자가 key를 알게 되면 메시지를 쉽게 복호화할 수 있기 때문에 key를 안전하게 보호해야 한다.

- asymmetric encryption(비대칭 키 암호화): <span style="color:orange">암호화에 사용하는 key와 복호화에 사용하는 key가 서로 다르다.</span>

    일반적으로 두 개의 key가 사용되며, 하나는 public key(공개 키)이고 다른 하나는 private key(개인 키)이다. public key는 다른 사람들에게 공개되어 메시지를 암호화하는 데 사용되고, private key는 소유자만이 가지고 있으며 암호화된 메시지를 복호화하는 데 사용된다.

> symmetric encryption은 하나의 key를 공유하여 사용하는 방식<br>
> asymmetric encryption은 public key와 private key라는 서로 다른 두 개의 key를 이용하여 데이터를 보호하는 암호화 방식

### Symmetric Encryption
통신을 하는 두 당사자가 같은 key를 공유해야 하며, 이 key를 이용하여 메시지를 암호화하고 복호화한다.

대칭 키 암호화를 이용한 통신에서는 먼저 key 교환(key exchange) 과정이 필요하다. 이 key 교환은 두 가지 방식으로 이루어질 수 있다. 첫 번째는 통신하는 두 당사자 사이에서 직접 key를 교환하는 방법이다. 두 번째는 신뢰할 수 있는 제3자(trusted third party)를 통해 key를 교환하는 방법이며, 예를 들어 certificate authority와 같은 기관이 이를 지원할 수 있다.

대표적으로 사용되는 대칭 키 암호화 알고리즘에는 DES(Data Encryption Standard)와 AES(Advanced Encryption Standard)가 있다. DES는 과거에 널리 사용되던 암호화 표준이지만 보안성이 약해지면서 현재는 AES가 더 널리 사용되고 있다. AES는 높은 보안성과 효율성을 제공하여 현대의 다양한 보안 시스템과 네트워크 통신에서 표준 암호화 방식으로 사용되고 있다.

---

### Asymmetric Encryption
이 개념은 Diffie와 Hellman에 의해 처음 제안되었다. 이 방식에서는 누구나 수신자의 public key를 이용하여 메시지를 암호화할 수 있지만, 메시지를 실제로 복호화할 수 있는 것은 해당 수신자가 가지고 있는 private key뿐이다. 따라서 네트워크에서 다른 사람이 통신 내용을 가로채더라도 private key가 없으면 메시지를 해독할 수 없다.

비대칭 암호화 방식의 대표적인 알고리즘으로는 RSA 알고리즘이 있다. RSA는 Rivest, Shamir, Adleman에 의해 개발된 알고리즘으로, 현재 가장 널리 사용되는 비대칭 암호화 알고리즘 중 하나이다. RSA는 공개 키와 개인 키의 쌍을 이용하여 데이터를 암호화하고 복호화하며, 인터넷 보안 통신과 같은 다양한 보안 시스템에서 중요한 역할을 한다.

---

### Authentication
메시지를 보낸 사람의 신원을 확인하고, 메시지가 전송 과정에서 변조되지 않았음을 확인하기 위한 보안 기능이다.

**Encryption**은 <span style="color:orange">메시지를 읽을 수 있는 수신자의 범위를 제한하는 역할을 한다.</span> 올바른 key를 가진 수신자만이 메시지를 복호화하여 내용을 확인할 수 있도록 하여 메시지의 기밀성을 보호한다.

**Authentication**은 <span style="color:orange">메시지를 보낼 수 있는 송신자의 범위를 제한하는 역할을 한다.</span> 즉, 메시지가 실제로 주장하는 송신자에 의해 보내졌는지를 확인하여, 다른 사람이 송신자를 가장하여 메시지를 보내는 것을 방지한다.

Authentication은 메시지가 전송되는 과정에서 내용이 변경되지 않았다는 것을 확인하는 데에도 유용하다. 이를 통해 수신자는 메시지가 원래 송신자가 보낸 그대로의 내용인지 확인할 수 있으며, 메시지의 무결성을 보장할 수 있다.

---

### Components of an authentication algorithm
Authentication 알고리즘은 메시지의 송신자를 확인하고 메시지가 변조되지 않았는지를 검증하기 위해 여러 구성 요소로 이루어져 있다.

먼저 key의 집합 K가 있다. 이 key는 인증 과정에서 사용되는 비밀 정보로, 메시지의 인증 값을 생성하거나 검증하는 데 사용된다.

다음으로 message의 집합 M이 있으며, 이는 송신자가 보내는 원래의 메시지들을 의미한다.

또한 authenticator의 집합 A가 있다. authenticator는 메시지에 대해 생성되는 인증 값으로, 메시지의 무결성과 송신자의 신원을 확인하기 위해 사용된다.

인증 값을 생성하기 위해 secure(hash) function S가 사용된다. 이 함수는 key와 message를 입력으로 받아 authenticator를 생성한다. 즉, S : K → (M → A)의 형태로 표현되며, 특정 key와 메시지를 이용하여 해당 메시지의 인증 값을 계산하는 역할을 한다.

마지막으로 verification function V가 있다. 이 함수는 메시지와 authenticator를 입력으로 받아 해당 메시지가 올바른지 여부를 검사한다. 즉, V : K → (M × A → {true, false})의 형태로 표현되며, 올바른 key와 authenticator가 사용된 경우 true를 반환하고, 그렇지 않은 경우 false를 반환한다.

따라서 Authentication 알고리즘은 key, message, authenticator, 그리고 인증 값을 생성하는 함수와 이를 검증하는 함수를 통해 메시지의 송신자와 무결성을 확인하는 구조로 이루어져 있다.

--- 

### The property of an authentication algorithm
Authentication 알고리즘의 중요한 성질은 올바른 key를 가진 경우에만 유효한 인증 값(authenticator)을 생성할 수 있다는 점이다.

올바른 key를 가진 시스템만이 메시지에 대해 유효한 authenticator를 생성할 수 있다. key를 보유한 컴퓨터는 메시지에 대한 authenticator를 생성할 수 있으며, 같은 key를 가지고 있는 다른 컴퓨터들은 verification function을 이용하여 그 authenticator가 올바른지 검증할 수 있다.

key k를 가지고 있지 않은 컴퓨터는 메시지에 대한 올바른 authenticator를 생성할 수 없다. 그렇기 때문에 공격자가 메시지를 위조하거나 송신자를 가장하여 메시지를 보내는 것이 어렵게 된다.

> Authentication 알고리즘은 비밀 key를 기반으로 메시지의 송신자를 확인하고 메시지가 위조되지 않았음을 보장하는 특성을 가진다.

---

### Two types of authentication algorithm
Authentication 알고리즘은 메시지의 송신자를 확인하고 메시지가 전송 과정에서 변조되지 않았는지를 검증하는 데 사용된다.

- hash function: 메시지 m을 입력으로 받아 작은 크기의 고정된 데이터 블록을 생성한다. 이 값은 message digest 또는 hash value라고 불린다. 해시 함수는 같은 메시지에 대해 항상 같은 해시 값을 생성하지만, 해시 값만으로 원래 메시지를 역으로 계산하는 것은 매우 어렵도록 설계되어 있다. 따라서 메시지의 무결성을 확인하는 데 사용된다.

- MAC(Message Authentication Code): 비밀 key를 이용하여 생성되는 암호학적 체크섬이다. MAC은 메시지와 secret key를 함께 사용하여 인증 값을 생성하며, 수신자는 같은 key를 이용하여 이 값을 검증한다. 이를 통해 메시지가 변조되지 않았는지 확인할 수 있고, 메시지가 key를 공유하는 올바른 송신자로부터 왔는지도 확인할 수 있다.

- Digital Signature Algorithm(디지털 서명 알고리즘): 메시지에 대해 디지털 서명(digital signature)을 생성하며, 누구나 공개된 public key를 이용하여 메시지의 진위 여부를 검증할 수 있다. 그러나 서명을 생성할 수 있는 것은 private key를 가진 사용자뿐이다. 

    디지털 서명은 특히 매우 유용한 기술인데, 이는 public key로부터 private key를 계산하는 것이 계산적으로 거의 불가능하기 때문이다. 이러한 특성 때문에 디지털 서명은 전자 문서 인증, 보안 통신, 그리고 블록체인과 같은 기술에서 널리 사용된다. 예를 들어 BitCoin과 같은 블록체인 시스템에서도 디지털 서명을 이용하여 거래의 진위와 소유권을 확인한다.


---

### Protection
Protection은 컴퓨터 시스템에서 정의된 자원에 대해 프로세스와 사용자의 접근을 제어하는 것을 의미한다. 즉, 시스템에 존재하는 파일, 메모리, CPU와 같은 자원에 대해 권한이 있는 사용자나 프로세스만 접근할 수 있도록 관리하는 기능이다. 이를 통해 시스템 자원이 무단으로 사용되거나 잘못 변경되는 것을 방지할 수 있다.

Protection은 공유 자원(shared resources)을 사용하는 복잡한 시스템의 신뢰성(reliability)을 높이는 역할을 한다. 여러 사용자와 프로세스가 동시에 같은 자원을 사용할 경우, 적절한 접근 제어가 이루어지지 않으면 충돌이나 오류가 발생할 수 있기 때문이다.

현대의 컴퓨터 시스템은 인터넷과 같은 **보안이 완전히 보장되지 않는 통신 환경(insecure communication platforms)** 과 연결되어 있기 때문에, Protection 메커니즘을 통해 시스템 자원에 대한 접근을 적절하게 제한하고 관리하는 것이 매우 중요하다.

---


## Principles of Protection
The Principle of Least Privilege는 시스템 보호에서 매우 중요한 기본 원칙이다. 이 원칙은 오랜 시간 동안 사용되어 온 보호 원칙으로, 보안과 시스템 안정성을 높이기 위해 적용된다.

이 원칙의 핵심은 프로세스, 사용자, 그리고 시스템에 필요한 **최소한의 권한만 부여해야 한다는 것이다.** 즉, 어떤 작업을 수행하는 데 필요한 만큼의 권한만 주고, 그 이상은 허용하지 않도록 하는 것이다. 이렇게 하면 권한이 과도하게 부여되는 것을 방지하고, 보안 위험을 줄일 수 있다.

UNIX 시스템에서는 사용자와 파일에 대한 권한 관리 기능이 제공된다. 대표적으로 root 사용자, sudo 명령어, 그리고 chmod 명령어 등이 있다. root는 시스템 전체에 대한 최고 권한을 가진 사용자이고, sudo는 일반 사용자가 필요한 경우에만 관리자 권한으로 명령을 실행할 수 있게 해 준다. 또한 chmod는 파일에 대한 읽기, 쓰기, 실행 권한을 설정하는 데 사용된다.

이러한 권한 관리와 최소 권한 원칙을 적용하면, 사용자가 불필요하게 높은 권한을 가지는 상황을 줄일 수 있으며, 만약 시스템이 공격을 받더라도 피해 범위를 줄이는 데 도움이 된다. 따라서 The Principle of Least Privilege는 악의적인 공격을 완화하고 시스템의 보안을 강화하는 데 중요한 역할을 한다.


---

### Access Matrix
Access Matrix는 보호(protection)를 설명하는 일반적인 모델로, 시스템에서 누가 어떤 자원에 어떤 방식으로 접근할 수 있는지를 표현하는 추상적인 모델이다.

이 모델에서는 시스템의 보호 구조를 행렬(matrix) 형태로 나타낸다. 행(row)은 주체(subject)를 나타내며, 일반적으로 사용자나 프로세스를 의미한다. 열(column)은 객체(object)를 나타내며, 파일, 메모리, 장치, 프로그램과 같은 시스템 자원을 의미한다.

행렬의 각 칸에는 해당 주체가 특정 객체에 대해 수행할 수 있는 접근 권한(access rights)이 기록된다. 예를 들어 읽기(read), 쓰기(write), 실행(execute)과 같은 권한이 포함될 수 있다.

Access Matrix 방식에서 행렬의 행(row)은 domain을 나타내고, 열(column)은 object를 나타낸다. 여기서 domain은 특정 사용자나 프로세스가 가지는 접근 권한의 집합을 의미하며, object는 파일, 메모리, 장치 등과 같은 시스템 자원을 의미한다.

행렬의 각 칸에는 해당 domain이 특정 object에 대해 가질 수 있는 접근 권한(access rights)의 집합이 저장된다. 이러한 접근 권한에는 읽기(read), 쓰기(write), 실행(execute)과 같은 다양한 권한이 포함될 수 있다.

이러한 접근 권한을 실제로 관리하는 방법 중 하나가 **ACL(Access Control List)** 이다. ACL은 특정 object에 대해 어떤 사용자나 domain이 어떤 권한을 가지고 있는지 목록 형태로 관리하는 방식이다. 즉, Access Matrix의 한 열(column)에 해당하는 정보를 실제 시스템에서 구현한 형태라고 볼 수 있다.

## Other Protection Methods

### Sandboxing
Sandboxing은 프로세스를 실행할 때 그 프로세스가 수행할 수 있는 작업을 제한된 환경 안에서 실행하도록 하는 보안 기법이다. 즉, 프로그램이 시스템 전체에 자유롭게 접근하지 못하도록 하고, 정해진 범위 안에서만 동작하도록 격리된 환경을 제공한다.

일반적으로 하나의 프로세스는 **그 프로세스를 실행한 사용자의 권한(credentials)** 을 그대로 사용하여 실행된다. 따라서 해당 사용자가 접근할 수 있는 파일, 자원, 시스템 기능 등에 프로세스도 접근할 수 있게 된다. 이 경우 프로그램에 취약점이 있으면 사용자의 권한 범위 내에서 시스템에 피해를 줄 가능성이 있다.

Sandboxing은 이러한 위험을 줄이기 위해 프로세스의 접근 권한과 실행 환경을 제한하여 시스템에 미칠 수 있는 영향을 최소화한다.

예를 들어 Java와 .NET 환경에서는 가상 머신(virtual machine) 수준에서 sandboxing을 적용하여 프로그램이 허용된 범위 안에서만 실행되도록 한다. 또한 Android 운영체제에서는 강제 접근 제어(mandatory access control) 정책을 사용하여 애플리케이션을 서로 격리된 환경에서 실행하도록 하며, 이를 통해 각 앱이 다른 앱이나 시스템 자원에 무단으로 접근하지 못하도록 한다.

### Code Signing
시스템이 프로그램이나 스크립트를 신뢰할 수 있는지 확인하기 위해 사용되는 보안 기술이다. 기본적으로 시스템에서는 어떤 프로그램이 안전한지, 또는 악의적으로 변경되었는지를 확인할 필요가 있다.

예를 들어 프로그램이나 스크립트가 배포된 이후에 누군가에 의해 코드가 수정되었다면, 그 프로그램은 원래 개발자가 만든 것과 다른 동작을 할 수 있으며 보안 위험이 발생할 수 있다. 이러한 문제를 방지하기 위해 사용되는 방법이 Code Signing이다.

Code Signing은 프로그램이나 실행 파일(executable)에 디지털 서명(digital signature)을 추가하는 과정이다. 이 서명을 통해 해당 프로그램이 생성된 이후 변경되지 않았다는 것을 확인할 수 있다. 만약 코드가 수정되었다면 디지털 서명이 일치하지 않게 되므로 시스템은 이를 감지할 수 있다.

이 기술은 다양한 분야에서 사용된다. 예를 들어 운영체제의 배포 파일, 시스템 패치, 그리고 제3자 프로그램(3rd party tools)을 배포할 때 Code Signing이 사용된다. 또한 Android나 iOS와 같은 모바일 플랫폼에서도 애플리케이션에 Code Signing을 적용하여 앱의 무결성과 개발자의 신뢰성을 확인하도록 하고 있다.
