## CPU Scheduling
#### CPU Scheduling 이란
    운영체제가 프로세스들에게 CPU 자원을 어떻게 배분할지 결정하는 메커니즘이다.
    컴퓨터 시스템 내에서 프로세스는 CPU 사용과 입출력 대기(I/O Burst) 상태를 반복하며 실행되는데 특정 프로세스가 입출력을 기다리는 동안 CPU를 놀게하는 것은 매우 비효율적이므로 이때 다른 프로세스에게 CPU를 넘겨줌으로써 자원 활용도를 극대화하기 위해 스케줄링이 필요하다.

#### 주요 스케줄링 알고리즘
    스케줄링 방식은 크게 선점형(preemptive), 비선점형(Non-preemptive)으로 나뉜다.

    - 선점형은 OS가 강제로 CPU를 뺏어 다른 프로세스에 주는 방식이다.
  
    - 비선점형은 프로세스가 스스로 종료하거나 대기 상태로 가기전까지 CPU를 독점한다. 문맥 교환 부하가 적으나 한 프로세스가 길어지면 나머지는 계속 대기하게 된다.


#### 스케줄링이 결정되는 시점
    1. Running -> Waiting: [ Non Preemptive ]
        프로세스가 CPU를 쓰다가 I/O요청을 하면 스스로 CPU를 반납한다.

    2. Running -> Ready: [ Preemptive or Non Preemptive ]
        실행중이던 프로세스를 강제로 Ready 상태로 보낸다.
        이 때 계속 그 프로세스를 다시 실행할지 아니면 다른 프로세스를 실행할지 선택한다.

    3. Waiting -> Ready: [ Preemptive or Non Preemptive ]
        기다리던 프로세스가 준비 완료된 상태로 돌아온다.
        지금 실행 중인 프로세스를 계속 실행할지 새로 준비된 프로세스를 실행할지 결정한다.

    4. Running -> Terminated: [ Non Preemptive ]
        CPU가 비었으므로 반드시 다른 프로세스를 선택해야 한다.


#### 디스패처
    디스패처는 프로세스 실행 흐름을 제어하며 커널 모드에서 실행된다.

    - 문맥 교환
        1. 현재 CPU에서 실행 중인 프로세스의 상태(레지스터 값, 프로그램 카운터 등)를 PCB(Process Control Block)에 저장한다.
        2. 새로 선택된 프로세스의 상태를 PCB로부터 복구하여 CPU에 로드한다.

    - 사용자 모드 전환
        운영체제(커널 모드)가 할 일을 마쳤으므로, 제어권을 다시 사용자 프로그램에게 넘기기 위해 CPU의 실행 모드를 사용자 모드로 변경한다.

    - 프로그램 재개(Jumping)
        새로운 프로세스가 이전에 멈췄던 지점(또는 처음 시작점)의 메모리 주소로 점프하여 실행을 재개한다.

    * 디스패처 지연: 디스패처가 하나의 프로세스를 멈추고 다른 프로세스를 실행하는데 걸리는 시간을 Dispatch Latency라고 한다. 이 시간 동안 CPU는 실제 유저 작업을 하지 못하는 오버헤드 상태가 된다. 따라서 시스템 성능을 높이기 위해서는 디스패처가 최대한 빠르게 동작해야한다.

> 커널 모드와 유저 모드: CPU는 실행 권한을 엄격하게 나누어 관리한느데 이를 이중 동작 모드라고 한다. 두 모드는 CPU가 현재 수행하고 있는 작업의 권한 수준을 나타낸다. 이는 프로그램에 악성 프로그램이나 버그로 인해 중요한 시스템 파일에 접근할 수 있는 경우를 방지하기 위해 존재하며 유저 모드는 Sandbox 역할을 한다.

#### 스케줄링의 성능 척도
    1. CPU Utilization: CPU를 얼마나 쉬지 않고 가동하는지
    2. Throughput: 단위 시간당 얼마나 많은 작업을 끝내는지
    3. Turnaround Time: 프로세스가 시작해서 끝날 때까지 걸린 총 시간
    4. Waiting Time: Ready Queue에서 기다린 시간의 합
    5. Response Time: 요청을 제출한 시점부터 첫 번째 응답이 도착할 때까지 걸린 시간

#### 스케줄링 알고리즘
    1. FCFS (First-Come, First-Served)
       - 가장 단순한 방식으로 '선착순'이다. 큐에 도착한 순서대로 CPU를 할당한다.
       - 비선점형이고 CPU를 할당받으면 끝날 때까지 사용한다.
       - Convoy Effect: 실행 시간이 아주 긴 프로세스가 앞에 있으면 뒤에 있는 짧은 프로세스들이 끝없이 기다려야하는 문제가 발생한다.
       - FIFO queue로 간단하게 구현할 수 있다.

    2. SJF (Shortest Job First)
       - 가장 짧은 일을 먼저 처리한다.
       - 평균 대기 시간을 최소화하는데 최적(Optimal)이다
       - SRTF (Shortest Remaining Time First): SJF의 선점형(Preemptive) 버전이다. 새로운 프로세스가 왔을 때, 현재 남은 시간보다 더 짧은 프로세스가 오면 CPU를 뺏어서 새 프로세스에게 할당한다.
       - Starvation: 긴 작업들은 짧은 작업들에 밀려 영원히 실행되지 못하는 기아 현상이 생길 수 있다.
       - 다음 CPU Burst의 길이를 알 수 있는 방법은 없기 때문에 과거의 데이터를 바탕으로 미래를 예측하는 근사(Approximate) 방식을 사용한다. 

    3. Round-Robin
       - 선점형이며 시간이 다 되면 다음 프로세스에서 CPU를 넘기고 줄 맨 뒤로 간다.
       - 모든 프로세스가 공평하기 기회를 얻으며 응답 시간(Response Time)이 매우 빠르다.
       - 시간 할당량이 너무 크면 FCFS가 되고 너무 작으면 Context Switching 오버헤드가 커진다.
    
    4. Priority-based
       - 각 프로세스에 우선순위 점수를 매겨서 높은 점수부터 실행한다.
       - 선점/비선점형 둘 다 가능 하다.
       - SJF과 동일하게 Starvation 문제가 있으나 기다린 시간에 비례해서 우선순위를 점차 높여주는 Aging 기법을 사용하여 기아 현상을 해결한다.

    5. MLQ (Multi-Level Queue / Priority-based Preemptive Scheduling with Round-Robin)
       - 스케줄러는 Ready Queue에 있는 프로세스 중 우선순위 숫자가 가장 높은 프로세스를 먼저 선택한다.
       - 우선순위가 같은 프로세스가 여러 개 있다면 이들 사이에서는 시간 할당향(Time Quantum)을 두어 공평하게 CPU를 번갈아 가며 사용한다.
       - Starvation은 동일하게 발생하며 프로세스가 끊임없이 들어온다면 우선순위가 낮은 프로세스는 평생 실행되지 못할 수 있다. Aging기법으로 낮은 수선순위 큐에서 오래 대기한 프로세스의 우선순위를 점진적으로 높여준다.
