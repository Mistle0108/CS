## Mass-Storage Structure
Mass Storage는 컴퓨터 시스템에서 사용하는 **비휘발성(Non-volatile)** 2차 저장 장치를 의미한다.

**비휘발성(Non-volatile)** 이란 전원이 꺼져도 데이터가 사라지지 않고 계속 보존된다는 특징을 가진다는 뜻이다. 이러한 저장 장치는 운영체제, 프로그램, 사용자 파일 등 장기간 보관해야 하는 데이터를 저장하는 데 사용된다.

일반적으로 Mass Storage 장치로는 **HDD(Hard Disk Drive)** 나 **NVM(Non-Volatile Memory)** 과 같은 저장 장치가 사용된다. 또한 경우에 따라 자기 테이프(Magnetic Tape), 광 디스크(Optical Disk), 또는 **클라우드 저장소(Cloud Storage)** 와 같은 다양한 저장 매체가 사용되기도 한다.

대용량 저장 시스템에서는 RAID(Redundant Array of Independent Disks) 구조를 사용하기도 한다. RAID는 여러 개의 디스크를 하나의 시스템처럼 묶어 사용하여 데이터의 안정성, 저장 성능, 그리고 저장 용량을 향상시키는 방식이다.

### HDD Scheduling
HDD Scheduling은 하드 디스크에서 여러 개의 입출력 요청이 들어왔을 때 디스크 접근 순서를 효율적으로 결정하는 방법을 뜻한다. 

HDD 스케줄링의 주요 목적
- 디스크 접근 시간(access time), 특히 탐색 시간(seek time)을 최소화
- 데이터 전송 대역폭(data transfer bandwidth)을 최대화

**Seek Time(탐색 시간)** 은 디스크 장치의 헤드가 원하는 데이터가 위치한 실린더(cylinder)까지 이동하는 데 걸리는 시간을 의미하며, 이때 **Rotational Latency(회전 지연 시간)** 가 발생하는데, 이는 디스크 플래터(platter)가 회전하여 원하는 섹터(sector)가 헤드 아래에 올 때까지 기다리는 추가적인 시간을 말한다.

이러한 시간들이 디스크 접근 시간의 중요한 요소가 된다.

**Disk Bandwidth(디스크 대역폭)** 은 첫 번째 요청이 시작된 시점부터 마지막 데이터 전송이 완료될 때까지의 총 시간 동안 실제로 전송된 데이터의 총 바이트 수를 기준으로 계산된다. 전체 전송된 데이터 양을 총 소요 시간으로 나눈 값으로 정의되며, 디스크 시스템의 데이터 처리 효율을 나타내는 지표이다.


### FIFO Scheduling
FIFO Scheduling은 디스크 스케줄링 방식 중 하나로, 요청이 도착한 순서대로 디스크 작업을 처리하는 방식이다.

이 방식은 모든 요청을 순서대로 처리하기 때문에 **본질적으로 공정한(fair) 방식** 이라는 장점이 있다. 특정 요청이 계속 뒤로 밀리는 일이 없으며, 모든 요청이 동일한 기준으로 처리된다.

- 디스크 헤드의 이동 거리를 고려하지 않고 단순히 요청 도착 순서만을 기준으로 처리하기 때문에 일반적으로 가장 빠른 서비스를 제공하지는 못한다. 
- 디스크 헤드가 먼 거리를 계속 이동해야 할 수 있기 때문에 탐색 시간(seek time)이 증가하고 전체 성능이 비효율적일 수 있다.


### SCAN Scheduling
SCAN Scheduling은 디스크 스케줄링 알고리즘 중 하나로, 디스크 헤드가 엘리베이터처럼 한 방향으로 이동하면서 요청을 처리하는 방식이다. 이 때문에 Elevator Algorithm이라고도 불린다.

이 방식에서는 디스크 암(disk arm)이 디스크의 한쪽 끝에서 시작하여 반대쪽 끝 방향으로 이동하면서 지나가는 실린더에 대한 요청을 순서대로 처리한다. 즉, 이동 경로에 있는 요청들을 차례로 처리하면서 **헤드가 계속 한 방향으로 이동** 한다.

디스크 헤드가 디스크의 끝에 도달하면 이동 방향을 반대로 바꾸고, 다시 반대 방향으로 이동하면서 해당 경로에 있는 요청들을 계속 처리한다. 이러한 과정을 반복하면서 디스크 요청들을 처리하게 된다.

SCAN 스케줄링은 FIFO 방식보다 디스크 헤드의 이동을 체계적으로 관리할 수 있기 때문에 평균 탐색 시간(seek time)을 줄일 수 있고, 전체적인 디스크 접근 성능을 향상시키는 장점이 있다.


### C-SCAN (Circular-SCAN) Scheduling
C-SCAN (Circular-SCAN) Scheduling은 SCAN 스케줄링을 변형한 디스크 스케줄링 알고리즘으로, 요청들의 대기 시간을 보다 균등하게 만들기 위해 설계된 방식이다.

디스크 헤드가 디스크의 한쪽 끝에서 다른 쪽 끝 방향으로 이동하면서 지나가는 실린더의 요청들을 순서대로 처리한다. SCAN 방식과 마찬가지로 이동 경로에 있는 요청들을 처리하며 헤드가 한 방향으로 계속 이동한다.

그러나 SCAN과 달리, 헤드가 디스크의 끝에 도달하면 방향을 바꾸지 않는다. 대신 아무 요청도 처리하지 않은 채 즉시 디스크의 시작 위치로 이동한 후 다시 같은 방향으로 이동하면서 요청을 처리한다.

디스크의 실린더들을 하나의 원형 구조(circular list)처럼 간주하여 마지막 실린더에서 다시 첫 번째 실린더로 이어지는 구조로 처리한다. 이러한 특성 때문에 모든 요청이 비교적 균등한 대기 시간을 가지게 되어 SCAN보다 더 일정한 응답 시간을 제공할 수 있다.

### Boot Block
Boot Block은 컴퓨터가 전원이 켜졌을 때 처음 실행되는 초기 프로그램을 저장하는 영역을 의미한다. 컴퓨터 시스템이 동작을 시작하려면 가장 먼저 실행될 프로그램이 필요하며, 이 프로그램이 운영체제를 메모리에 적재하고 시스템을 초기화하는 역할을 한다.

이 초기 프로그램을 **Bootstrap Loader(부트스트랩 로더)** 라고 한다. Bootstrap Loader는 일반적으로 NVM(Non-Volatile Memory) 플래시 메모리에 저장되어 있으며, 전원이 켜지면 CPU가 접근할 수 있는 미리 정해진 메모리 위치(known memory location)에 매핑되어 실행된다.

Bootstrap Loader는 시스템의 기본적인 하드웨어를 초기화한 뒤 저장 장치에 있는 운영체제 커널을 메모리로 불러와 실행하게 한다.

### RAID: Redundant Arrays of Independent Disks
RAID는 여러 개의 디스크를 하나의 저장 시스템처럼 묶어 사용하는 디스크 구성 기술들의 집합을 의미한다. RAID는 다양한 디스크 조직 기법을 포함하고 있으며, 저장 장치의 성능 향상과 데이터 신뢰성 향상을 목적으로 사용된다.

RAID는 여러 개의 디스크를 병렬(parallel)로 동작하도록 구성할 수 있기 때문에 데이터 읽기(read)와 쓰기(write)의 속도를 향상시킬 수 있다. 여러 디스크가 동시에 작업을 수행함으로써 데이터 처리 속도를 높일 수 있기 때문이다.

중복 정보(redundant information)를 여러 디스크에 저장하는 방식을 사용하여 데이터 저장의 신뢰성(reliability)을 높일 수 있다. 이러한 중복 저장 구조 덕분에 하나의 디스크가 고장 나더라도 데이터가 손실되지 않도록 보호할 수 있다.

Parallelism을 이용해 여러 개의 디스크를 동시에 사용하여 데이터 처리 성능을 향상시키는 방법이 있다. 여러 드라이브를 병렬로 동작시키면 하나의 디스크만 사용할 때보다 데이터 전송 속도(transfer rate)를 크게 향상시킬 수 있다. 이러한 성능 향상을 위해 RAID에서는 데이터 스트라이핑(strip­ing) 기법을 사용한다.

Striping은 데이터를 여러 디스크에 나누어 저장하는 방식으로, 여러 드라이브가 동시에 데이터를 읽거나 쓸 수 있도록 하여 데이터 전송 속도를 높이는 역할을 한다.

  - Bit-level Striping은 하나의 바이트(byte)를 구성하는 각 비트를 여러 디스크에 나누어 저장하는 방식이다. 예를 들어 8개의 드라이브가 있을 경우, 각 바이트의 i번째 비트를 i번째 드라이브에 저장하는 방식으로 데이터가 분산된다. 이 방식은 여러 디스크가 동시에 동작하기 때문에 높은 병렬성을 제공할 수 있다.
  - Block-level Striping은 데이터를 비트 단위가 아닌 블록(block) 단위로 나누어 여러 디스크에 저장하는 방식이다. 즉, 하나의 데이터 블록을 여러 디스크에 순서대로 분산 저장하는 방식으로, 여러 개의 드라이브에 일반적으로 적용할 수 있는 확장된 형태의 스트라이핑 방식이다.

### RAID Level
RAID Levels은 여러 RAID 구성 방식들을 **비용(cost)과 성능(performance) 사이의 균형 관계(cost-performance trade-off)** 에 따라 분류한 것이다. 각 RAID 수준은 데이터 저장 방식과 중복 저장 방법이 서로 다르며, 이에 따라 성능, 신뢰성, 저장 효율이 달라진다.

1. Mirroring 방식은 동일한 데이터를 두 개 이상의 디스크에 그대로 복사하여 저장하는 방식이다. 이 방법은 하나의 디스크가 고장 나더라도 다른 디스크에 동일한 데이터가 남아 있기 때문에 데이터 신뢰성이 매우 높다는 장점이 있다. 그러나 같은 데이터를 여러 번 저장해야 하므로 저장 공간이 많이 필요하고 비용이 높다는 단점이 있다.

2. Striping 방식은 데이터를 여러 디스크에 나누어 저장하는 방법으로, 여러 디스크가 동시에 동작할 수 있기 때문에 데이터 읽기와 쓰기 성능이 매우 효율적이다. 하지만 데이터가 단순히 분산 저장되기 때문에 데이터의 신뢰성을 보장하는 기능은 없다는 한계가 있다.

3. 이러한 문제를 보완하기 위해 Parity Bit(패리티 비트) 개념이 사용된다. 패리티 비트는 데이터의 오류를 검출하기 위해 추가되는 비트로, 예를 들어 데이터 비트의 개수가 짝수이면 패리티 비트를 1로 설정하고, 홀수이면 0으로 설정하는 방식 등을 사용할 수 있다. **이러한 방식은 데이터 비트 중 하나가 손상되었을 경우 오류를 감지할 수 있도록 해준다.**


##  I/O Systems
컴퓨터의 두 가지 주요 작업은 **입출력(I/O, Input/Output)** 과 **연산(Computing)** 이다.

실제로 많은 컴퓨터 사용 환경에서는 연산보다 입출력 작업이 더 큰 비중을 차지하는 경우가 많다. 

예를 들어 웹 브라우징, 파일 편집, 유튜브 시청, 게임 실행 등과 같은 작업들은 대부분 데이터를 읽고 쓰거나 네트워크를 통해 데이터를 주고받는 과정이 중심이 되기 때문에 I/O 작업의 비중이 크다.

### Memory-Mapped I/O
Memory-Mapped I/O는 프로세서가 입출력 장치를 제어하기 위해 장치의 레지스터들을 메모리 주소 공간에 매핑하여 접근하는 방식을 의미한다. CPU는 별도의 I/O 명령어를 사용하는 대신 일반적인 메모리 읽기와 쓰기 연산을 통해 장치를 제어할 수 있다.

프로세서가 I/O 전송을 수행하기 위해서는 장치 컨트롤러(controller)에 명령과 데이터를 전달해야 한다. 이를 위해 컨트롤러는 데이터와 제어 신호를 처리하기 위한 여러 개의 레지스터(register)를 가지고 있다.

1. Data-in Register는 입력 데이터를 저장하는 레지스터로, 호스트(프로세서)가 이 레지스터를 읽어서 입력 데이터를 가져온다.
   
2. 반대로 Data-out Register는 출력 데이터를 저장하는 레지스터로, 호스트가 이 레지스터에 데이터를 기록하여 장치로 데이터를 보낸다.
   
3. Status Register는 장치의 상태 정보를 담고 있으며, 호스트가 이 레지스터를 읽어 장치의 현재 상태(예: 준비 상태, 작업 완료 여부 등)를 확인할 수 있다.
   
4. Control Register는 장치의 동작을 제어하기 위한 레지스터로, 호스트가 여기에 값을 기록하여 특정 명령을 시작하거나 장치의 동작 모드를 변경할 수 있다.

Memory-Mapped I/O는 장치 제어 레지스터를 프로세서의 메모리 주소 공간에 직접 매핑하여 사용하는 입출력 방식이다. 이 방식에서는 장치의 제어 레지스터들이 일반 메모리처럼 프로세서의 주소 공간(address space)에 포함된다.

장치가 Memory-mapped I/O를 지원하는 경우, 장치의 제어 레지스터(control registers)가 프로세서의 물리 메모리 주소(physical memory address)에 매핑된다. 따라서 CPU는 이 레지스터들을 별도의 특별한 I/O 명령어가 아니라 **일반적인 데이터 전송 명령어(load, store 등)** 를 사용하여 접근할 수 있다.

> CPU는 해당 물리 메모리 주소에 읽기(read) 또는 쓰기(write) 연산을 수행함으로써 장치 제어 레지스터에 접근하고 I/O 요청을 실행한다. 이러한 방식은 메모리 접근과 I/O 접근을 동일한 방식으로 처리할 수 있게 해 주기 때문에 구조가 단순하고 프로그래밍이 편리하다는 장점이 있다.

### Three types of I/O
컴퓨터 시스템에서 입출력(I/O)을 처리하는 방식은 크게 Polling, Interrupt, DMA(Direct Memory Access)의 세 가지로 나눌 수 있다. 각각의 방식은 CPU와 I/O 장치가 상호작용하는 방법이 다르며, 상황에 따라 서로 다른 방식이 사용된다.

1. Polling: Busy-waiting이라고도 불리며, CPU가 장치의 상태 레지스터(status register)를 계속 반복해서 확인하는 방식이다. CPU는 장치가 작업 중인지 나타내는 busy 비트를 지속적으로 읽다가, 이 비트가 해제되어 장치가 준비되었다는 것을 확인하면 다음 작업을 수행한다. 이 방식은 구현이 단순하지만, CPU가 계속 상태를 확인해야 하므로 CPU 자원이 낭비될 수 있다는 단점이 있다.
   
2. Interrupt: CPU에는 **interrupt-request line**이 존재하며, 장치가 작업을 완료하거나 처리가 필요할 때 이 것을 통해 CPU에 신호를 보낸다. CPU가 인터럽트를 감지하면 현재 수행 중인 작업을 잠시 중단하고 **ISR(Interrupt Service Routine)**이라는 인터럽트 처리 루틴으로 이동하여 해당 작업을 처리한다. 이때 **ISR의 주소는 인터럽트 interrupt vector table**에 저장되어 있어 CPU가 적절한 처리 루틴으로 이동할 수 있다. 이 방식은 CPU가 계속 상태를 확인할 필요가 없기 때문에 Polling보다 효율적이다.

3. DMA(Direct Memory Access): DMA는 Programmed I/O처럼 CPU가 한 번에 한 바이트씩 데이터를 처리하는 방식의 비효율을 줄이기 위해 사용되는 방법이다. DMA에서는 DMA 컨트롤러가 CPU 대신 메모리와 장치 사이의 데이터 전송을 직접 수행한다. 따라서 CPU는 데이터 전송 과정에 거의 개입하지 않으며, 대량의 데이터를 빠르게 전송해야 하는 경우에 매우 유용하다.

### Blocking I/O .vs. Non-blocking I/O
Blocking I/O와 Non-blocking I/O는 입출력 작업을 수행할 때 스레드(thread)의 실행이 어떻게 처리되는지에 따라 구분되는 방식이다.

- Blocking I/O: 입출력 작업이 완료될 때까지 해당 스레드의 실행이 중단되는 방식이다. 스레드는 더 이상 실행되지 않고 Running Queue에서 Waiting Queue로 이동하여 대기 상태가 된다.  <span style="color:orange">**입출력 작업이 완료된 후에야 다시 실행 가능한 상태로 돌아와 작업을 계속 수행할 수 있다.** </span>

- Non-blocking I/O: 입출력 요청을 하더라도 스레드의 실행이 중단되지 않는 방식이다. 입출력 장치가 준비되지 않았더라도 가능한 만큼의 데이터만 먼저 반환하고, 스레드는 계속해서 자신의 코드를 실행할 수 있다. <span style="color:orange"> **예를 들어 워드 프로세서에서 키보드나 마우스 입력을 처리하는 경우, 프로그램은 입력을 기다리는 동안에도 다른 작업을 계속 수행할 수 있다.** </span>

### The difference between non-blocking and asynchronous system call
Non-blocking 시스템 호출과 Asynchronous 시스템 호출의 차이는 입출력 요청 이후 데이터 처리 방식과 완료 시점에서 나타난다.

Non-blocking read() 시스템 호출은 호출 즉시 바로 반환된다. 이때 함수는 현재 사용 가능한 데이터만 반환하며, 요청한 바이트 수 전체를 반환할 수도 있고, 일부만 반환하거나 전혀 반환하지 않을 수도 있다. **데이터가 충분히 준비되지 않았더라도 시스템 호출은 기다리지 않고 즉시 종료** 되며, 프로그램은 이후에 다시 호출하여 추가 데이터를 읽을 수 있다.

synchronous read() 시스템 호출은 입출력 작업 자체를 비동기적으로 요청하는 방식이다. 이 호출은 데이터 전송을 요청한 뒤 전체 데이터 전송이 완료될 때까지 백그라운드에서 작업이 진행되도록 한다. 프로그램의 스레드는 호출 이후에도 계속 자신의 코드를 실행할 수 있으며, 데이터 전송은 미래의 어느 시점에 완료된다. 작업이 완료되면 운영체제는 알림이나 이벤트 등을 통해 프로그램에 결과를 전달한다.

- Non-blocking I/O는 즉시 반환하면서 현재 가능한 데이터만 제공하는 방식이고
- Asynchronous I/O는 전체 작업을 요청한 뒤 백그라운드에서 완료되도록 하는 방식이라는 차이가 있다.

#### Non-blocking I/O 예시
```
채팅 프로그램에서 소켓(socket)으로 데이터를 읽을 때 프로그램이 read()를 호출했는데 현재 네트워크 버퍼에 100바이트만 도착해 있고, 1000바이트를 요청했다면

- 프로그램: read(socket, buffer, 1000)
- 실제 도착 데이터: 100바이트

이 경우 Non-blocking read()는 다음처럼 동작한다.

- 함수가 즉시 반환된다.
- 현재 가능한 100바이트만 읽어서 반환한다.
- 데이터가 없다면 0바이트를 반환할 수도 있다.
- 프로그램은 나중에 다시 read()를 호출해서 남은 데이터를 읽는다.

> CPU는 계속 실행되지만 프로그램이 여러 번 확인해야 한다.
```

#### Asynchronous I/O 예시
```
파일을 디스크에서 읽을 때 프로그램이 1000바이트 읽기 요청을 한다.

- 프로그램이 1000바이트 읽기 요청을 한다.
- 프로그램: async_read(file, buffer, 1000)

이 경우 Asynchronous I/O는 다음처럼 동작한다.

- 프로그램이 읽기 요청만 보낸다.
- 운영체제가 백그라운드에서 디스크에서 1000바이트를 모두 읽는다.
- 프로그램은 기다리지 않고 다른 코드 실행
- 읽기가 완료되면 인터럽트 / 콜백 / 이벤트로 프로그램에 알림

> 프로그램이 다시 read()를 호출할 필요 없이 OS가 작업을 끝까지 처리한다.
```

> Non-blocking: 바로 돌아오지만 데이터가 일부만 올 수 있음<br>
> Asynchronous: 작업을 끝까지 맡겨놓고 나중에 완료 알림

## File-System Interface
운영체제에서 데이터와 프로그램을 저장하고 접근할 수 있도록 하는 메커니즘을 제공하는 시스템이다. 파일 시스템은 운영체제와 사용자 모두가 사용할 수 있는 데이터와 프로그램을 온라인 상태로 저장하고 관리하며, 필요할 때 쉽게 접근할 수 있도록 하는 역할을 한다.

파일 시스템은 크게 두 가지 주요 구성 요소로 이루어져 있다.

1. 파일(file): 각각의 파일은 서로 관련된 데이터를 저장하는 단위로, 프로그램 코드나 문서, 이미지와 같은 다양한 형태의 데이터를 담고 있다.

2. 디렉터리 구조(directory structure): 디렉터리는 시스템에 존재하는 모든 파일들을 체계적으로 정리하고 관리하는 구조로, 파일들을 그룹화하고 계층적으로 조직하여 사용자가 파일을 쉽게 찾고 접근할 수 있도록 한다.


### Access Methods
**Access Methods(접근 방법)** 은 파일에 저장된 데이터를 어떤 방식으로 읽거나 쓰는지를 나타내는 방법이다.

- Sequential Access(순차 접근): 파일에 저장된 정보를 처음부터 끝까지 순서대로 처리하는 방법이다. 이 방식에서는 각 레코드(record)가 차례대로 하나씩 처리되며, 앞의 데이터를 건너뛰고 바로 뒤의 데이터를 읽는 것이 어렵다. 따라서 데이터를 한 레코드씩 순서대로 읽거나 쓰는 방식으로 처리된다. 이러한 접근 방식은 테이프 저장 장치와 같은 순차적 저장 매체에서 주로 사용된다.

- Direct Access(직접 접근) 또는 Relative Access(상대 접근): 파일이 고정 길이의 논리적 레코드들로 구성되어 있는 경우에 사용된다. 이 방식에서는 특정 레코드의 위치를 직접 지정하여 원하는 레코드를 순서에 상관없이 빠르게 읽거나 쓸 수 있다. 즉, 프로그램이 필요한 위치의 데이터를 바로 접근할 수 있기 때문에 데이터 처리 속도가 빠르고 효율적이다.

### Allocation Method
파일 시스템에서 파일을 저장하기 위해 디스크 공간을 어떻게 할당할 것인지 결정하는 방법이다. 파일 시스템을 구현할 때의 주요 문제 중 하나는 파일에 저장 공간을 어떻게 배치할 것인가이다. 저장 공간을 효율적으로 활용하면서도 파일에 빠르게 접근할 수 있도록 하는 방법을 설계하는 것이 중요하다.

파일 시스템에서는 일반적으로 세 가지 주요 할당 방법이 사용된다.

- Contiguous Allocation: 파일을 디스크의 연속된 블록 공간에 저장하는 방법으로, 파일의 모든 데이터가 서로 인접한 위치에 저장된다. 이 방법은 구조가 단순하고 파일 접근 속도가 빠르다는 장점이 있지만, 디스크 공간이 분산되면 연속된 공간을 확보하기 어려워지는 단점이 있다.

- Linked Allocation: 파일을 구성하는 각 블록이 포인터를 통해 서로 연결된 형태로 저장된다. 따라서 파일의 블록들이 디스크에 연속적으로 위치할 필요가 없으며, 빈 공간이 있는 곳에 자유롭게 저장할 수 있다. 그러나 특정 위치의 데이터를 읽기 위해서는 처음부터 연결을 따라가야 하므로 접근 속도가 느려질 수 있다는 단점이 있다.

- Indexed Allocation: 인덱스 블록(index block)을 사용하여 파일이 저장된 디스크 블록들의 위치를 관리한다. 이 방식은 Linked Allocation에서 발생하는 문제를 해결하기 위해 제안되었다. 

    Linked Allocation 방식에서는 각 데이터 블록 안에 다음 블록을 가리키는 포인터가 함께 저장되기 때문에, 이러한 포인터들이 디스크의 여러 블록에 분산되어 존재하게 된다. 그 결과 특정 블록을 찾기 위해서는 연결된 블록들을 순서대로 따라가야 하므로 접근 속도가 느려질 수 있는 문제가 있다.

    Indexed Allocation은 이러한 문제를 해결하기 위해 파일에 대한 모든 블록 주소를 하나의 인덱스 블록에 모아 관리하는 방식을 사용한다.

    각 파일마다 하나의 인덱스 블록이 존재하며, 이 인덱스 블록은 디스크에 저장된 데이터 블록들의 주소를 배열 형태로 저장한다. 즉, 인덱스 블록의 i번째 항목(entry)은 해당 파일의 i번째 데이터 블록을 가리키는 주소를 포함한다.

### FAT
파일 시스템에서 파일이 디스크의 어떤 블록에 저장되어 있는지를 관리하기 위한 파일 할당 테이블 방식이다. FAT는 Linked Allocation(연결 할당) 방식의 한 변형으로, 보다 효율적으로 파일 블록을 관리하기 위해 사용된다.

Linked Allocation 방식의 단점은 주로 순차 접근(sequential access) 파일에만 효과적으로 사용될 수 있다는 점이다. 파일의 특정 블록, 예를 들어 i번째 블록을 찾기 위해서는 파일의 첫 번째 블록부터 시작하여 연결된 블록들을 하나씩 따라가야 한다. 이 과정 때문에 파일의 중간 데이터에 접근하는 속도가 느려질 수 있다.

이러한 문제를 해결하기 위해 사용되는 방법이 **FAT(File Allocation Table)** 이다. FAT는 간단하면서도 효율적인 구조를 가지며, 파일이 차지하고 있는 디스크 블록들의 연결 정보를 하나의 테이블 형태로 관리한다.

FAT 방식에서는 각 디스크 볼륨(volume)의 시작 부분에 일정한 저장 공간을 할당하여 파일 할당 테이블을 저장한다. 이 테이블에는 **디스크의 각 블록에 대한 하나의 엔트리(entry)** 가 존재하며, **블록 번호를 기준으로 인덱싱(indexing)** 된다.

각 엔트리에는 다음에 연결된 블록의 번호가 저장되어 있어, 운영체제는 이 테이블을 통해 파일을 구성하는 블록들의 순서를 쉽게 추적할 수 있다. 이를 통해 디스크 블록의 연결 정보를 빠르게 확인할 수 있어 Linked Allocation보다 효율적으로 파일을 관리할 수 있다.

### Free-Space Management
파일 시스템에서 디스크의 사용 가능한 공간을 관리하는 방법이다.

파일 시스템은 새로운 파일을 저장하거나 기존 파일의 크기를 확장할 때 비어 있는 디스크 블록을 찾아 할당해야 하기 때문에, 현재 사용되지 않고 남아 있는 공간을 효율적으로 관리하는 것이 중요하다.

이를 위해 파일 시스템은 free-space list을 유지한다. 이 목록에는 현재 사용되지 않고 비어 있는 디스크 블록들의 정보가 저장되어 있으며, 시스템은 이 정보를 이용하여 새로운 파일이 생성되거나 파일이 확장될 때 사용 가능한 블록을 빠르게 찾아 할당할 수 있다.

또한 파일이 삭제되면 해당 파일이 사용하던 디스크 블록은 다시 free-space list에 추가되어 다른 파일이 사용할 수 있는 공간으로 관리된다.
