## Main Memory
프로세스는 실행 중인 프로그램을 의미한다. 이는 디스크에 저장되어 있는 프로그램 파일이 아닌 메인 메모리에 적재되어 CPU에 의해 실제로 실핸되고 있는 명령어들의 집합을 말한다.

메모리는 작은 저장공간들이 연속적으로 나열된 구조이며 각 공간은 주소를 통해 구분된다. 

CPU는 프로그램 카운터(PC)를 이용하여 메모리로부터 명령어를 가져온다(fetch). 프로그램 카운터는 다음에 실행할 명령어의 주소를 저장하고 있는 레지스터이다.

명령어를 실행하는 과정에서 CPU는 메모리로부터 데이터를 읽어올 수 있으며(load) 메모리에 데이터를 저장할 수도 있다(store).

프로그램이 실행되는 동안 메모리와의 데이터 교환이 계속해서 이루어진다.


### Memory space
메모리 공간에서는 각 프로세스가 서로 독립된 메모리 공간을 가져야 한다. 이는 한 프로세스가 다른 프로세스의 메모리 영역을 침범하지 못하도록하여 시스템의 안정성과 보안을 보장하기 위함이다.

이러한 보호를 위해 베이스 레지스터와 리밋 레지스터라는 한 쌍의 레지스터가 사용된다. 
- 베이스 레지스터(base register)는 해당 프로세스가 사용할 수 있는 메모리 영역의 시작 주소를 저장하고,
- 리밋 레지스터(limit register)는 그 영역의 크기(또는 범위)를 저장한다.

CPU가 메모리에 접근할 떄마다 현재 접근하려는 주소가 베이스 레지스터와 리밋 레지스터가 지정한 legal한 범위 안에 있는지 확인한다. 주소가 허용된 범위를 벗어나면 운영체제는 이를 오류로 간주하고 해당 프로세스를 중단시킨다.

메모리 공간의 보호는 CPU하드웨어에 의해 수행된다. CPU는 user mode에서 생성되는 모든 메모리 주소를 레지스터의 값과 비교함으로써 메모리 보호를 수행한다. 

사용자 프로그램이 어떤 메모리 주소에 접근하려고 할 때마다 CPU는 그 주소가 베이스 레지스터와 리밋 레지스터가 전한 범위 안에 있는지 검사한다. 생성된 주소가 허용된 범위 내에 있다면 접근이 허용되지만 범위를 벗어난 경우에는 하드웨어가 즉시 예외를 발생시켜 운영체제에 제어를 넘긴다.

## Address Binding
주소 바인딩은 프로그램의 주소가 실제 메모리 주소로 결정되는 과정이다. 

프로그램은 디스크에 바이너리 실행 파일의 형태로 저장되어 있다. 이 프로그램이 실행되기 위해서는 먼저 메모리로 적재되어야 한다. 이때 프로세스의 시작 주소는 반드시 00000000에서 시작하는 것이 아니라 운영체제가 할당한 임의의 메모리 위치에서 시작하게 된다.

소스코드에서 사용되는 주소는 일반적으로 symbolic address이다. ***컴파일러*** 는 symbolic address를 relocation address로 변환한다. relocation address는 프로그램이 메모리의 어느 위치에 적재되더라도 조정될 수 있는 주소를 의미한다.

이후 링커나 로더는 이 relocation address를 실제 메모리의 절대 주소로 변환한다. 이 과정을 통해 프로그램은 메모리의 특정 위치에 정확히 배치되어 실행될 수 있게된다. 즉, 주소 바인딩은 

- 프로그래머가 작성하는 사람이 이해하기 쉬운 이름으로 Symbolic Address를 작성한다.
- 컴파일러는 symbolic address를 숫자로 바꾸지만 실제 메모리의 어디에 올라갈지는 모른다. 프로그램의 시작 위치를 기준으로 한 상대적인 주소일 뿐이다. 그래서 프로그램이 메모리에 할당될 때 상대적인 위치로 다시 배치할 수 있도록하여 재배치 가능(relocatable) 하다고 부른다.
- 운영체제가 프로그램을 실제 메모리에 올릴 주소를 Absolute Address라고 한다. 이는 프로그램이 메모리에 적재될 때(loading time) 시작 위치(base Address)가 정해지고 relocation address에 따라 symbolic address가 Absolute Address로 변환된다.


### Binding
1. Compile-time Binding
컴파일 타임 바인딩은 프로그램을 컴파일 하는 시점에 절대 주소가 결정되는 방식이다. 이 방식에서는 프로그램이 메모리의 특정 위치에서 실행될 것이라고 가정하므로 시작 주소가 미리 정해져 있다. 따라서 프로그램이 다른 메모리 위치에 적재되어야 한다면 다시 컴파일 해야한다. 이 방식은 구조가 단순하지만 메모리 사용의 유연성이 부족하다.

2. Load-time Binding
로드 타임 바인딩은 프로그램이 메모리에 적재될 때 절대 주소가 결정되는 방식이다. 컴파일 단계에서는 재배치 가능 주소가 생성되고, 프로그램이 실제 메모리에 올라갈 때 로더가 시작 위치를 정한 후 이를 기준으로 주소를 한 번에 변환한다. 이 방식은 프로그램을 다양한 위치에 적재할 수 있지만, 일단 실행이 시작되면 메모리 위치를 변경할 수 없다.

3. Execution-time Binding
실행 시간 바인딩은 프로그램이 실행되는 동안 주소 변환이 이루어지는 방식이다. CPU가 메모리에 접근할 때마다 논리 주소를 절대 주소로 변환하며 이 과정은 하드웨어(MMU)에 의해 수행된다. 이 방식은 실행 중에도 메모리 위치를 변경할 수 있어 매우 유연하다.

## Logical, Physical Address Space
논리 주소(Logical Address)는 프로그램이 실행되면서 CPU가 만들어내는 주소이며, 이를 가상 주소(virtual address)라고도 한다.

논리 주소 공간(Logical Address Space)은 사용자 프로그램에 의해 생성되는 모든 논리 주소들의 집합을 의미한다. 즉, 프로그램이 접근할 수 있다고 생각하는 주소 범위 전체를 말한다.

물리 주소(Physical Address)는 실제 메모리 장치에서 사용되는 주소를 의미한다. 이는 메모리 주소 레지스터(memory-address register)에 적재되어 실제로 메모리에 전달되는 주소이다.

물리 주소 공간(Physical Address Space)은 이러한 논리 주소들에 대응되는 실제 물리 메모리 주소들의 집합을 의미한다. 즉, 실제 RAM 상에서 존재하는 주소 범위를 말한다.


## MMU(Memory Management Unit - H/W)
CPU --- **(logical address)** ---> MMU --- **physical address** ---> Physical memory

MMU(Memory Management Unit)는 논리 주소를 물리 주소로 변환해 주는 하드웨어 장치이다. CPU가 생성한 논리 주소는 직접 메모리로 전달되지 않고, 먼저 MMU를 거쳐 물리 주소로 매핑된다.

프로그램은 자신이 연속된 메모리 공간을 사용하는 것처럼 보이지만, 실제로는 MMU가 주소를 변환하여 물리 메모리의 다른 위치에 접근하도록 한다.

이 과정을 통해 운영체제는 각 프로세스에 독립적인 주소 공간을 제공할 수 있으며, 메모리 보호와 가상 메모리 구현이 가능해진다.

MMU에는 재배치 레지스터가 포함되어 있으며 이는 베이스 레지스터라고도 불린다. 재배치 레지스터는 현재 실행 중인 프로세스가 메모리에서 시작하는 물리적 주소를 저장하고 있다. CPU가 생성한 논리 주소는 MMU를 거치면서 이 재배치 레지스터의 값과 더해져 최종적인 물리 주소로 변환된다.

Example)

- (CPU) CPU generates logical address 346
- (MMU) The relocation register contains 14000
- (Memory) The MMU adds them to produce physical address 14346

## Dynamic Loading
Dynamic Loading은 프로그램의 코드와 데이터를 전부 물리 메모리에 적재해야할 필요가 있는가에서부터 시작한다. 

Dynamic Loading에서는 프로그램의 전체를 한 번에 메모리에 적재하지 않는다. 대신 특정 루틴은 실제로 호출될 때까지 메모리에 올리지 않는다.
필요할 때만 해당 코드가 적재된다. 자주 사용되지 않는 루틴을 미리 적재해 둘 필요가 없기 떄문에 전체 메모리 사용량을 줄일 수 있다. 

어떤 루틴이 처음 호출되면 relocatable linking loader가 실행되어 해당 루틴을 메모리에 적재한다. 이후 프로그램의 주소 테이블을 갱신하여 새로 적재된 루틴의 위치를 반영한다.


## Dynamic Linking과 Shared Libraries(공유 라이브러리)
**Dynamic Linking과 Shared Libraries(공유 라이브러리)** 는 프로그램과 라이브러리를 언제, 어떻게 연결하느냐에 대한 개념이다.

DLL(Dynamically Linked Library)은 프로그램이 실행될 때 동적으로 연결되는 시스템 라이브러리를 의미한다. 프로그램이 시작된 이후에 필요한 라이브러리가 연결된다.

Static Linking(정적 연결)은 시스템 라이브러리를 일반 객체 모듈과 동일하게 취급하여, 로더가 실행 파일을 만들 때 라이브러리 코드까지 함께 결합하는 방식이다. 이 경우 라이브러리 코드가 실행 파일 안에 포함되므로, 각 프로그램은 자신의 복사본을 가지게 된다.

Dynamic Linking(동적 연결)은 동적 적재(dynamic loading)와 유사하지만, 차이점은 적재가 아니라 링크가 실행 시점까지 지연된다는 것이다. 컴파일 시점이 아니라 프로그램이 실행되는 동안 라이브러리와의 연결이 이루어진다.

DLL은 Shared Library(공유 라이브러리)라고도 불린다. 이는 메인 메모리에 DLL의 인스턴스가 하나만 존재하고, 이를 여러 사용자 프로세스가 함께 공유할 수 있기 때문이다. 이 방식은 메모리 사용량을 줄이고, 라이브러리 업데이트를 더 쉽게 만드는 장점이 있다.

## Contiguous Memory Allocation
연속 메모리 할당은 메인 메모리를 효율적으로 사용하기 위한 기본적인 메모리 관리 기법이다.

OS는 메인메모리를 가능한 한 효율적으로 할당해야한다. 일반적으로 메모리는 두 개의 큰 영역으로 나뉜다. 하나는 OS가 상요하는 영역이고 다른 하나는 사용사 프로세스들이 사용하는 영역이다. 여러 유저 프로세스가 동시에 메모리에 적재되어 실행되기 때문에 문제는 대기 중인 프로세스들에게 가용 메모리를 어떻게 할당할 것인가이다.

연속 메모리 할당 방식에서는 각 프로세스가 메모리 내에서 하나의 연속된 영역을 차지한다. 한 프로세스는 무리적으로 이어진 하나의 구간에만 배치되며 그 다음 프로세스는 그 옆의 또 다른 연속된 구간을 차지하는 구조이다.

이 방식은 구현이 단순하다는 장점이 있지만 시간이 지나면서 메모리의 빈 공간이 조각나는 외부 단변화(external fragmentation) 문제가 발생할 수 있다.

## Memory Protection
프로세스는 자신에게 할당되지 않은 메모리 영역에 접근하지 말아야한다. 이를 막는 기법을 Memory Protection라고 한다. 이를 위해 relocation register와 limit register를 사용한다.

relocation register는 해당 프로세스가 메모리에 적재된 base address를 저장한다. CPU가 생성한 logical address는 이 relocation register 값과 더해져 실제 물리 주소로 변환된다.

limit register는 프로세스가 사용할 수 있는 메모리 범위의 크기를 나타낸다. CPU가 어떤 논리 주소를 생성하면 먼저 그 주소가 0 이상이고 limit 값보다 작은지를 검사한다. 이 범위를 벗어나면 OS가 trap을 발생시켜 접근을 차단한다.

- 논리 주소 < limit 인지 확인하고
- 통과하면 물리 주소 = relocation register + 논리 주소

두 레지스터를 조합함으로써 각 프로세스는 자신에게 할당된 연속된 메모리 영역 안에서만 실행될 수 있으며, 다른 프로세스나 운영체제 영역을 침범할 수 없게 된다.

## Memory Allocation
Memory Allocation에서 가장 단순한 방법 중 하나는 Variable-Partition Scheme이다.

메모리를 고정된 크기로 나누지 않고 프로세스의 크기에 맞추어 가변적인 크기의 파티션을 동적으로 생성한다. 각 파티션에는 정확히 하나의 프로세스만 적재된다. 프로세스가 메모리에 들어올 때 필요한 크기만큼 연속된 공간을 할당받는다.

이때 현재 어떤 프로세스에도 할당되지 않은 빈 메모리 공간을 hole 이라고 부른다. 새로운 프로세스가 적재될 대 이 홀 중 하나가 선택되어 할당된다. 

가변 분할 방식은 메모리를 보다 유연하게 사용할 수 있다는 장점이 있지만 시간이 지남에 따라 작은 홀들이 흩어져 존재하게 되는 외부 단편화가 발생할 수 있다.


### The Problem of Dynamic Storage Allocation
동적으로 공간을 할당하게 되면, 크기 n의 메모리 요청이 들어왔을 때 현재 사용한 여러 개의 빈 공간(hole) 중에서 어떤 공간을 선택해 할당할 것인가를 결정하는 것이다. 운영체제는 메모리 안에 흩어져 있는 여러 hole 중 하나를 선택하여 프로세스를 적재해야 하며 이를 위한 세 가지 방법이 존재한다.

- First-Fit: 메모리를 앞에서부터 순차적으로 탐색하다가 요청 크기 이상인 첫 번째 hole을 발견하면 그 공간을 바로 할당한다. 구현이 간단하고 탐색 시간이 비교적 짧다는 장점이 있지만 메모리의 앞부분에 작은 단편들이 많이 생길 수 있다.'

- Best-Fit: 요청을 수용할 수 있는 hole들 중 가장 작은 hile을 선택하여 할당한다. 남은 공간을 최적화하려는 전략이지만 모든 hole을 탐색해야하므로 시간이 더 오래 걸린다. 또한 아주 작은 크기의 hole이 많이 남아 외부 단편화가 심해질 수 있다.

- Worst-Fit: 가장 큰 hole을 선택하여 그 공간을 분할해 할당한다. 이론적으로는 할당 후에도 비교적 큰 공간이 남기 때문에 작은 단편이 덜 생길 것이라고 기대하지만 실제로는 메모리 활용 효율이 떨어지는 경우가 많다.

## Fragmentation
외부 단편화(external fragmentation)는 메모리 공간이 여러 개의 작은 hole(빈 공간)들로 나뉘어 흩어지는 현상을 의미한다. 전체적으로 보면 충분한 총 메모리 공간이 존재할 수 있지만, 그 공간들이 서로 인접해 있지 않고 떨어져 있기 때문에 하나의 큰 연속 공간을 필요로 하는 요청을 만족시킬 수 없는 상황이 발생한다.

내부 단편화(internal fragmentation)는 프로세스에 할당된 메모리 공간이 실제로 요청한 크기보다 약간 더 클 때 발생한다. 이때 남는 공간은 해당 파티션 내부에 존재하지만 다른 프로세스가 사용할 수 없다. 즉, 할당은 되었지만 사용되지 않는 메모리가 파티션 내부에 낭비되는 것이 내부 단편화이다.



## Paging
페이징은 프로세스의 물리적 주소 공간이 반드시 연속적일 필요 없도록 하는 매모리 관리 기법이다. 하나의 프로세스가 여러 개의 떨어진 물리 메모리 공간에 나뉘어 적재될 수 있다.

이 방식은 연속 메모리 할당 방식에서 발생하는 두 가지 주요 문제를 해결한다. 

첫째, 외부 단편화를 방지할 수 있다. 메모리를 고정된 크기의 블록으로 나누어 사용하기 때문에 작은 빈 공간들이 흩어져 생기는 문제를 줄일 수 있다.<br>
둘째, 외부 단편화를 해결하기 위해 필요한 comapction(메모리 재배치) 과정이 없어지므로 시스템 부담이 줄어든다. 

페이징은 운영체제와 하드웨어의 협력을 통해 구현되며, 운영체제는 페이지와 프레임을 관리하고, 하드웨어는 주소 변환을 빠르게 수행하여 논리 주소를 물리 주소로 변환한다.

- 페이징의 기본 방법은 먼저 물리 메모리를 동일한 크기의 고정 블록으로 나누는 것이다. 이 블록을 **프레임(frame)** 이라고 한다. 
- 동시에, 논리 메모리(프로세스의 주소 공간)도 같은 크기의 블록으로 나누는데 이를 **페이지(page)** 라고 한다.

이때 페이지의 크기와 프레임의 크기는 서로 같으며, 어떤 페이지든지 임의의 프레임에 적재될 수 있다.

논리 주소 공간과 물리 주소 공간이 완전히 분리된다. 즉, 프로세스는 자신만의 연속적인 논리 주소 공간을 사용하는 것처럼 보이지만, 실제 물리 메모리에서는 해당 페이지들이 여러 프레임에 흩어져 저장될 수 있다. 주소 변환은 페이지 테이블을 통해 이루어지며, 이를 통해 논리 주소가 적절한 물리 주소로 매핑된다.

페이징에서 CPU가 생성하는 모든 논리주소는 두 부분으로 나뉜다.
- Page number(p): 페이지 번호(p)는 해당 주소가 어떤 페이지에 속하는지를 나타내며, 이 값을 이용해 페이지 테이블에서 대응되는 물리 메모리의 프레임 번호를 찾는다. 
- page offset(d): 페이지 오프셋(d)는 그 페이지 내부에서의 위치를 의미한다. 페이지 안에서 몇 번째 바이트인지를 나타낸다.

주소 변환과정은 다음과 같다.
CPU가 생성한 논리 주소에서 페이지 번호p를 추출하고 이를 페이지 테이블의 인덱스로 사용하여 해당 페이지가 적재된 프레임 번호를 찾는다. 그런 다음 그 프레임 번호와 페이지 오프셋d를 결합하여 최종 물리 주소를 생성한다.

- 논리 주소 = (p,d)
- 물리주소 = (frame number, d)

이 방식 덕분에 프로세스의 논리 주소 공간은 연속적으로 보이지만 실제 물리 메모리에서는 여러 프레임에 분산되어 저장될 수 있다.

페이지 번호는 해당 프로세스가 가지고 있는 페이지 테이블의 인덱스로 사용된다.

CPU가 생성한 논리 주소에서 페이지 번호 부분은 그 프로세스의 페이지 테이블에서 대응되는 항목을 찾는 데 사용되며, 이를 통해 해당 페이지가 매핑된 물리 메모리의 프레임 번호를 확인할 수 있다.

## Page Table
페이지 테이블(Page Table)은 각 프로세스의 논리 주소를 물리 주소로 변환하기 위해 운영체제가 관리하는 자료구조이다. 모든 프로세스는 자신만의 페이지 테이블을 가지며, 이 테이블은 해당 프로세스의 논리 주소 공간을 물리 메모리의 어느 프레임에 매핑할 것인지를 기록한다.

페이지 테이블의 각 항목(Page Table Entry, PTE)에는 단순히 프레임 번호만 저장되는 것이 아니라, 여러 제어 정보도 함께 포함된다. 

예를 들어,
- 해당 페이지가 현재 메모리에 존재하는지를 나타내는 유효 비트(valid bit)
- 읽기/쓰기 가능 여부를 나타내는 보호 비트(protection bits)
- 최근에 참조되었는지를 표시하는 참조 비트(reference bit)
- 수정 여부를 나타내는 더티 비트(dirty bit) 등이 있다. 

이러한 정보들은 메모리 보호와 페이지 교체 알고리즘을 구현하는 데 사용된다.

페이지 테이블은 운영체제가 생성하고 관리하지만, 주소 변환 과정 자체는 하드웨어의 지원을 받는다. 
일반적으로 MMU(Memory Management Unit)가 페이지 테이블을 참조하여 주소 변환을 수행한다. 
다만, 매번 메모리를 두 번 접근하는 비용을 줄이기 위해 TLB(Translation Lookaside Buffer)라는 고속 캐시가 사용되며, 자주 사용되는 페이지 테이블 항목을 빠르게 조회할 수 있도록 한다.

결과적으로 페이지 테이블은 논리 주소 공간과 물리 주소 공간을 분리하면서도, 프로그램이 연속적인 메모리를 사용하는 것처럼 보이게 해 주는 핵심 메커니즘이라고 할 수 있다.

CPU가 논리 주소를 물리 주소로 변환하는 과정은 다음과 같이 이루어진다.

1. CPU는 생성된 논리 주소를 페이지 번호p와 오프셋으로 나눈다. 페이지 번호p를 해당 프로세스의 페이지 테이블에서 인덱스로 사용하여 대응되는 항목을 찾는다.
2. 페이지 테이블에서 해당 항목을 조회하면 그 페이지가 매핑되어 있는 물리 메모리의 프레임 번호f를 얻을 수 있다.
3. 마지막으로 논리 주소의 페이지 번호 p를 프레임 번호 f로 대체한다. 이렇게 얻은 프레임 번호에 기존의 오프셋을 그대로 결합하면 최종적인 물리 주소가 완성된다.

### Page size
페이지 크기(프레임 크기와 동일)는 하드웨어에 의해 결정된다. 일반적으로 페이지 크기는 2의 거듭제곱 형태로 설정되며, 보통 4KB에서 1GB 사이의 값이 사용된다.

논리 주소 공간의 크기가 2^m이고 페이지 크기가 2^n이라면, 하나의 논리 주소는 총 m비트로 표현된다. 이때 상위 m-n비트는 페이지 번호를 나타내고, 하위 n비트는 페이지 내부의 위치를 나타내는 오프셋으로 사용된다.

페이지 크기가 2의 거듭제곱이기 때문에 주소를 단순히 비트 단위로 나누는 것만으로 페이지 번호와 오프셋을 구분할 수 있으며, 이는 주소 변환을 효율적으로 수행할 수 있게 해준다.

프로세스가 몇 개의 페이지로 구성되는지를 계산한 뒤, 그 수만큼의 프레임을 물리 메모리에서 할당할 수 있는지를 검사한다. 할당 가능한 충분한 프레임이 존재하면, 운영체제는 해당 프레임들을 배정하고 페이지 테이블을 설정하여 논리 주소와 물리 주소 간의 매핑을 준비한다.

이를 위해 각 프로세스의 PCB(Process Control Block)에는 페이지 테이블을 가리키는 포인터가 다른 레지스터 값들과 함께 저장된다. 컨텍스트 스위치 시, 운영체제는 이 포인터 값을 복원하여 MMU가 올바른 페이지 테이블을 참조하도록 함으로써, 해당 프로세스의 논리 주소가 정확한 물리 주소로 변환되도록 한다.


### PTBR
PTBR(Page-Table Base Register)는 현재 실행 중인 프로세스의 페이지 테이블이 저장되어 있는 메모리 시작 주소를 가리키는 레지스터이다. 페이지 테이블은 메인 메모리에 저장되며, CPU가 주소 변환을 수행할 때 PTBR을 통해 해당 프로세스의 페이지 테이블 위치를 참조한다.

컨텍스트 스위치가 발생하면, 운영체제는 새로 선택된 프로세스의 페이지 테이블 주소를 PTBR에 로드한다. 이 방식은 페이지 테이블 전체를 교체하는 것이 아니라, 단지 기준 주소만 바꾸면 되므로 비교적 빠른 컨텍스트 스위치를 가능하게 한다.

그러나 메모리 접근 시간 측면에서는 오버헤드가 발생한다. 하나의 논리 주소를 실제 데이터에 접근하기 위해서는 먼저 페이지 테이블 항목을 읽어 프레임 번호를 확인해야 하고, 그 다음에 해당 물리 주소의 실제 데이터에 접근해야 한다. 따라서 기본적인 페이징 구조에서는 한 번의 데이터 접근을 위해 두 번의 메모리 접근이 필요하게 된다.


### TLB
Translation Look-aside Buffer(TLB)는 주소 변환 속도를 향상시키기 위해 사용되는 특수한 소형 하드웨어 캐시 메모리이다.

TLB는 최근에 참조된 페이지 테이블 항목들을 저장해 두는 빠른 조회용 메모리로, 일반 메인 메모리에 있는 페이지 테이블에 접근하는 대신 TLB를 먼저 확인함으로써 주소 변환 시간을 크게 줄일 수 있다.

CPU가 논리 주소를 생성하면, 먼저 TLB에서 해당 페이지 번호에 대한 매핑 정보가 존재하는지 확인한다. 
- 만약 TLB에 **원하는 항목이 있으면(TLB hit)**, 즉시 프레임 번호를 얻어 빠르게 물리 주소를 계산할 수 있다. 
- 반대로 **TLB에 해당 항목이 없으면(TLB miss)**, 메인 메모리에 있는 페이지 테이블을 참조하여 프레임 번호를 찾은 뒤, 그 결과를 TLB에 저장하여 이후 접근을 빠르게 만든다.

> TLB는 페이징 시스템에서 발생하는 이중 메모리 접근의 부담을 줄이기 위한 핵심적인 하드웨어 지원 장치이다.

### EAT
유효 메모리 접근 시간(Effective Memory-Access Time, EAT)은 TLB의 성능을 고려하여 실제로 평균적으로 걸리는 메모리 접근 시간을 의미한다.

TLB hit란 CPU가 참조하려는 페이지 번호가 TLB에 존재하는 경우를 말한다. 이 경우에는 페이지 테이블을 추가로 조회할 필요 없이 즉시 프레임 번호를 얻을 수 있으므로 한 번의 메모리 접근만으로 데이터에 도달할 수 있다.

TLB miss는 원하는 페이지 번호가 TLB에 없는 경우를 의미한다. 이때는 먼저 메인 메모리에 있는 페이지 테이블을 조회한 후, 실제 데이터에 접근해야 하므로 총 두 번의 메모리 접근이 필요하다.

**Hit ratio(적중률)** 는 전체 메모리 참조 중에서 TLB에서 원하는 항목을 찾은 비율을 의미한다. 적중률이 높을수록 평균 메모리 접근 시간은 줄어든다.

예를 들어, 메모리 접근 시간이 10ns이고 TLB 적중 시 1번 접근(10ns), 실패 시 2번 접근(20ns)이 필요하다고 가정하자.

적중률이 80%라면 평균 접근 시간은
**0.80×10+0.20×20=12ns 이다.**

적중률이 99%라면 
**0.99 × 10 + 0.01 × 20 = 10.1𝑛𝑠 이다.**

### Memory Protection with Paging
페이징 환경에서의 메모리 보호는 각 프레임(또는 페이지 테이블 항목)에 연결된 보호 비트들을 통해 이루어진다.

각 페이지 테이블 항목에는 일반적으로 valid-invalid 비트가 하나 추가로 포함된다. 이 비트는 해당 페이지가 현재 프로세스의 논리 주소 공간에 속하는지 여부를 나타낸다.

- valid로 설정되어 있으면, 그 페이지는 해당 프로세스의 합법적인(legal) 논리 주소 공간에 포함되어 있으며 접근이 허용된다.
- invalid로 설정되어 있으면, 그 페이지는 해당 프로세스의 논리 주소 공간에 속하지 않으므로 접근이 허용되지 않는다.

프로세스가 invalid로 표시된 페이지에 접근하려고 하면, 하드웨어는 이를 감지하여 예외(trap)를 발생시킨다. 이를 통해 운영체제는 불법적인 메모리 접근을 차단하고, 프로세스 간 메모리 보호를 보장할 수 있다.

### Shared Pages
페이징의 중요한 장점 중 하나는 공통 코드를 여러 프로세스가 공유할 수 있다는 점이다. 이는 다중 프로그래밍 환경에서 특히 중요한 요소이다.

예를 들어, 표준 C 라이브러리인 libc를 생각해 보자. 일반적으로 각 프로세스는 자신의 주소 공간에 libc의 복사본을 로드한다. 그러나 만약 해당 코드가 재진입 가능(reentrant) 코드라면, 하나의 물리 메모리 복사본을 여러 프로세스가 함께 공유할 수 있다.

**재진입 가능 코드는 실행 중에 자기 자신을 수정하지 않는 코드(non-self-modifying code)** , 즉 실행 과정에서 내용이 변경되지 않는 코드를 의미한다. 이러한 특성을 가지면 여러 프로세스가 동일한 물리 프레임에 매핑된 코드를 동시에 사용하더라도 충돌이 발생하지 않는다. 그 결과, 메모리 사용 효율이 향상되고 시스템 자원을 절약할 수 있다.

> 동일한 라이브러리같은 재진입 가능 코드를 사용하는 경우 물리 메모리에는 한 번만 적재하고 이를 사용하는 프로세스들에서 각자 따로 가지게 된다.

## Structuring the Page Table
논리 주소 공간이 커질수록 페이지 테이블 역시 매우 커질 수 있다. 페이지 테이블은 각 페이지마다 하나의 항목을 가져야 하므로, 주소 공간이 클 경우 그 크기 또한 기하급수적으로 증가하게 된다. 이로 인해 메모리 낭비가 발생하거나 관리 비용이 커질 수 있다.

이러한 문제를 해결하기 위해 페이지 테이블을 효율적으로 구성하는 여러 기법이 사용된다.
- 계층적 페이징(Hierarchical Paging): 계층적 페이징은 페이지 테이블을 여러 단계로 나누어 필요한 부분만 메모리에 두는 방식
- 해시 페이지 테이블(Hashed Page Table): 해시 함수를 이용해 페이지를 빠르게 찾도록 구성한 구조
- 역방향 페이지 테이블(Inverted Page Table): 물리 프레임을 기준으로 하나의 전역 테이블을 두어, 각 프레임이 어떤 프로세스의 어떤 페이지에 해당하는지를 기록하는 방식

### 계층적 페이징(Hierarchical Paging)
계층적 페이징(Hierarchical Paging)은 논리 주소 공간이 커짐에 따라 하나의 거대한 페이지 테이블을 사용하는 대신, 이를 여러 개의 단계로 나누어 관리하는 방식이다. 논리 주소 공간을 여러 개의 테이블 구조로 분할하여 필요한 부분만 메모리에 두도록 한다.

하나의 단일 페이지 테이블 대신, 상위 단계의 페이지 테이블이 하위 단계의 페이지 테이블을 가리키는 구조를 가진다. 예를 들어, 2단계 페이징에서는 논리 주소가 “페이지 디렉터리 인덱스”, “페이지 테이블 인덱스”, 그리고 “오프셋”으로 나뉜다. 먼저 상위 테이블(페이지 디렉터리)에서 하위 페이지 테이블의 위치를 찾고, 그 다음 하위 테이블에서 실제 프레임 번호를 찾는다.

이 구조의 장점은 사용되지 않는 주소 공간에 대한 페이지 테이블을 아예 생성하지 않아도 된다는 점이다. 따라서 매우 큰 논리 주소 공간을 가지는 시스템에서도 페이지 테이블의 메모리 사용량을 줄일 수 있다.

### 해시 페이지 테이블(Hashed Page Table)
해시 페이지 테이블(Hashed Page Table)은 32비트보다 큰 주소 공간을 다루기 위해 사용되는 기법이다. 주소 공간이 매우 커지면 전통적인 페이지 테이블은 지나치게 커지기 때문에, 이를 보다 효율적으로 관리하기 위해 해시 구조를 활용한다.

가상 페이지 번호(virtual page number)를 해시 함수의 입력으로 사용하여 해시 값을 계산하고, 그 결과에 해당하는 해시 테이블의 버킷(bucket)을 찾는다. 각 버킷에는 연결 리스트 형태로 여러 항목이 저장될 수 있으며, 각 항목에는 가상 페이지 번호와 이에 대응되는 물리 프레임 번호가 함께 기록된다.

주소 변환 시에는 먼저 가상 페이지 번호를 해시한 뒤, 해당 버킷에서 일치하는 페이지 번호를 탐색하여 대응되는 프레임 번호를 찾는다. 이 방법은 매우 큰 주소 공간에서도 페이지 테이블의 크기를 효율적으로 관리할 수 있도록 해 준다.

### 역방향 페이지 테이블(Inverted Page Table)
역방향 페이지 테이블(Inverted Page Table)은 전통적인 방식처럼 각 프로세스마다 페이지 테이블을 두는 대신, 시스템 전체에 대해 하나의 전역 테이블을 두는 방식이다.

이 구조에서는 물리 메모리의 각 프레임마다 하나의 항목(entry)이 존재한다. 즉, 페이지 수가 아니라 실제 물리 프레임 수만큼의 테이블 항목만을 가진다. 각 항목에는 해당 프레임에 적재되어 있는 가상 페이지 번호와, 그 페이지가 속한 프로세스에 대한 정보가 함께 저장된다.

주소 변환을 수행할 때는, 원하는 가상 페이지 번호와 프로세스 정보를 기준으로 테이블을 탐색하여 일치하는 항목을 찾는다. 일치하는 항목이 발견되면, 그 항목의 위치(프레임 번호)를 통해 물리 주소를 계산한다.

이 방식의 가장 큰 장점은, 매우 큰 논리 주소 공간을 갖는 시스템에서도 페이지 테이블의 크기가 물리 메모리 크기에 비례한다는 점이다. 그러나 단점으로는 주소 변환 시 검색 비용이 증가할 수 있어, 보통 해시 기법이나 TLB와 함께 사용하여 성능을 보완한다.


## Swappnig
스와핑(Swapping)은 시스템에 존재하는 모든 프로세스의 총 물리 주소 공간이 실제 물리 메모리의 크기를 초과하더라도 실행이 가능하도록 해 주는 기법이다. 이를 통해 동시에 메모리에 올라와 있는 프로세스 수를 늘릴 수 있으며, 결과적으로 시스템의 다중 프로그래밍 정도를 향상시킬 수 있다.

프로세스의 명령어와 데이터는 실행되기 위해 반드시 메모리에 존재해야 한다. 그러나 실행 중이 아닌 프로세스 전체 또는 그 일부는 일시적으로 메모리에서 보조 저장 장치(backing store)로 옮겨질 수 있다. 이후 다시 실행이 필요해지면, 해당 내용은 메모리로 다시 적재되어 실행을 계속한다.

이처럼 스와핑은 메모리와 보조 저장 장치 사이에서 프로세스를 교체함으로써 제한된 물리 메모리를 보다 효율적으로 활용하게 해 주는 메커니즘이다.

### Standard Swapping
Standard Swapping은 프로세스 전체를 메인 메모리와 보조 저장 장치(backing store) 사이에서 이동시키는 방식이다. 하나의 프로세스에 포함된 모든 코드와 데이터 영역을 통째로 메모리에서 내보냈다가, 다시 필요할 때 통째로 가져오는 구조이다.

그러나 프로세스 전체를 이동시키는 작업은 데이터의 양이 많기 때문에 디스크 I/O 비용이 매우 크다. 이로 인해 스와핑에 소요되는 시간이 상당히 길어질 수 있으며, 시스템 성능에 큰 부담을 준다. 따라서 전체 프로세스를 교체하는 방식은 비용이 지나치게 크다는 단점이 있다.

### Swapping with Paging
프로세스 전체를 교체하는 대신, 프로세스를 구성하는 일부 페이지 단위로 메모리와 보조 저장 장치 사이를 이동시키는 방식이다.

이 전략 역시 물리 메모리보다 더 많은 주소 공간을 사용하는 것을 가능하게 하지만, 한 번에 소수의 페이지만 교체하면 되므로 전체 프로세스를 이동시키는 것보다 훨씬 효율적이다.

오늘날 “페이징”이라고 할 때는 이러한 페이지 단위의 스와핑을 의미하는 경우가 많다. 

- 메모리에서 보조 저장 장치로 페이지를 내보내는 작업을 **페이지 아웃(page out)**
- 보조 저장 장치에서 메모리로 다시 가져오는 작업을 **페이지 인(page in)**

이 방식은 가상 메모리와 함께 사용될 때 특히 효과적이다. 필요한 페이지만 메모리에 유지하고 나머지는 디스크에 두는 구조이기 때문에, 제한된 물리 메모리를 효율적으로 활용할 수 있다.
